## Проверки именно этого прототипа

- `backend/tests`: **10 passed** после добавления тестов пользовательских галерей и ZIP. Покрыты последовательные загрузки, CSV в ZIP, построение версий индекса, поиск, превью и отказ для опасного пути/несовпадающего CSV. Отдельный тест доказывает единственную загрузку веса при восьми конкурентных холодных вызовах. Остались два предупреждения SQLAlchemy о старом `datetime.utcnow()` в унаследованной CRUD-модели.
- Docker Desktop macOS, Linux-контейнеры, CPU, gallery=750: `/ready` 200, реальный image+BBox `/api/identify` 200, OpenAPI, 10 негативных HTTP-кейсов, шесть real-image API-vs-export совпадений (в том числе 3 отказа).
- Повтор 10 последовательных и 12 конкурентных запросов (3 клиента), 0 ошибок и стабильный top-10 на итоговом образе: медиана/p95 полного последовательного HTTP **1,410/1,455 с**; concurrent 12 запросов за **18,022 с**, 0,666 завершённого запроса/с. Это локальный CPU, не официальный FPS. В состоянии покоя после холодного старта ML ~1,36 GiB; после конкурентной нагрузки наблюдали ~3,00 GiB. Docker Desktop limit 7,654 GiB. См. `mvp_local_benchmark_20260924.json`.
- При остановленном ML backend `/health`=200, `/ready`=503, `/api/identify`=503; после восстановления ML `/ready` вернулся к 200. Параллельная холодная загрузка сначала выявила OOM; singleton исправил его. Проверка 8 одновременных `/ready` после рестарта вернула 8×200, ML state `running`, `OOMKilled=false`.
- `mvp_bad_requests_20260924.json`, `mvp_api_export_parity_20260924.json`, `mvp_local_benchmark_20260924.json` содержат машинно-читаемые результаты. Визуальный UI, миллионная галерея, целевой GPU, официальный hidden mAP/F1 здесь не проверялись.
- ML-образ проверен с `docker run --network none`: E2+policy+gallery загрузились, запрос обработан, ожидаемый gallery ID оказался top-1; сеть контейнеру не предоставлялась.
- Повторная проверка после передачи задачи: оба контейнера `healthy`, 8/8 unit tests, 4 последовательных и 6 запросов при трёх клиентах без ошибок; медиана последовательного E2E HTTP 1,418 с, конкурентные 6 запросов за 9,135 с (0,657 запроса/с). После нагрузки ML-контейнер использовал около 1,5 GiB. Вывод записан в `/private/tmp/lct_mvp_recheck_20260924.json`; это дополнительная локальная проверка, не замер FPS жюри.
- После неё: текущий test suite 10/10. Реальный upload 5 файлов + 5 ZIP, query top-1 exact-match и сохранение после рестарта контейнеров прошли. Для demo cross-camera набора 14 фото пять кадров одной машины вошли в top-10 и были приняты. Это проверка ручного сценария, не новая оценка mAP/FPS.

## Переключение после полного обучения

Текущие артефакты оставлять неизменными как rollback. Для новой модели: версия и SHA веса → новая галерея и индекс → новая calibration/policy (пороги 0,394/0,112 нельзя переносить автоматически) → тесты runtime parity и API → новый test export → версия томов Compose. Backend HTTP-контракт можно сохранить.

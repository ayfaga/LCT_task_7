# Три сценария интерфейса ReID · 29.09.2026

После синхронизации с `origin/master` `2ec5b44` главная `/` ведёт к трём
рабочим действиям:

| Экран | Ввод | Действие |
| --- | --- | --- |
| `/gallery` | JPEG/PNG или ZIP, опциональный BBox CSV | `POST /api/galleries` и `/api/galleries/{id}/images`; ожидание индексации |
| `/many` | группа JPEG/PNG + обязательный `image_id,x,y,w,h` CSV | последовательный `/api/infer` для каждого запроса, CSV результатов |
| `/solo` | один JPEG/PNG + прямоугольник на исходном кадре | `/api/infer` с BBox в исходных пикселях, JSON результата |

Галерея из уже обрезанных автомобилей загружается без CSV. Для полных кадров
нужен manifest `filename,gallery_id,x,y,w,h`. При выборе отдельных JPEG/PNG
страница может преобразовать стандартный CSV организатора
`image_id,x,y,w,h` в этот manifest; для ZIP нужен готовый `manifest.csv`
внутри архива или отдельным файлом. Без manifest backend сознательно
индексирует весь кадр. Имена/ID должны быть уникальными; загрузка ограничена
200 фото за партию, 100 МиБ на ZIP, 1000 фото на галерею. Для исходного
многогигабайтного ZIP организатора используется streaming CLI из
`docs/ORGANIZER_ARCHIVE_IMPORT.md`, не браузерный импорт.

Legacy `/replenishment` и его данные не удалены, но этот маршрут только
сохраняет файлы и не строит поисковый индекс. Он больше не показан на главной.

Проверено локально без ML-сервиса: 37 Python-тестов, 8 Node-тестов;
страницы `/`, `/gallery`, `/many`, `/solo` открылись; на тестовом изображении
1200×800 ручное выделение показало BBox `x=136,y=99,w=895,h=544` и
активировало кнопку поиска. Это проверка координат/UI, **не** end-to-end
поиск настоящей моделью. Docker Desktop и ML-сервис на момент проверки
не работали; полноценный запрос и индексацию через этот экран нужно
повторить после запуска стека. Модель/веса/политика отказа не менялись.

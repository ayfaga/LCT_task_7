# Проверяемый экспорт для организаторов

Это **два интерфейса к одному и тому же** `backend/ml/import_organizer_archive.py`
и `backend/ml/export_test_hybrid.py`: консольный запуск для надёжной обработки
большого набора и отдельная страница `/judge-export` в прототипе. Они не
обучают модель, не используют скрытые метки и **не меняют** общую пользовательскую
галерею сайта. Сейчас они используют выбранный **strong DINOv2-L/14@336**
из `model_artifacts/strong_l336_aqe` и поставленный с ним бустинговый гибрид
отказа. Для группы из двух и более запросов применяется **transductive AQE**
к общему cohort query+gallery; для единственного запроса экспортёр явно
переходит на cosine, как `/solo`. `confidence` в CSV — численное исходное
cosine-сходство, **не вероятность**. Слова «mAP на скрытом тесте» из этих файлов
вывести нельзя: эталонные метки и официальный оценщик нам не даны.

## Два явных способа передать вход

**Готовый набор** принимает ZIP **или папку** с такой структурой (без
дополнительной папки-обёртки внутри ZIP):

```text
dataset.zip или dataset/
├── test_gallery.csv
├── test_query.csv
└── images/
    ├── <image_id>.jpg
    └── ...
```

**Четыре отдельных поля** принимают CSV галереи, изображения галереи, CSV
запросов и изображения запросов. Каждое поле изображений допускает один
или несколько ZIP, папок и отдельных JPEG одновременно. Например,
`gallery.csv + gallery.zip`, а для запросов `query.csv + папка query_images`
и ещё несколько отдельных JPEG. Внутри ZIP и папок допускаются вложенные
каталоги; сопоставление идёт по имени `<image_id>.jpg`/`.jpeg`, а не по
порядку файлов. CSV могут называться произвольно, но внутри обязательны
`image_id,x,y,w,h`. Повторный `image_id` внутри одной стороны — ошибка.
Галерея и запросы обрабатываются отдельно, поэтому один общий каталог
исходных JPEG можно указать для обеих сторон: используются только ID из
соответствующих CSV.

Оба CSV содержат столбцы `image_id,x,y,w,h`; `image_id` — уникальные
32-символьные lowercase hex ID в каждом CSV и не пересекаются между
query/gallery. Координаты `xywh` в пикселях **исходного** JPEG. Для каждого
CSV ID требуется один соответствующий JPEG. В готовом наборе он должен
лежать строго как `images/<image_id>.jpg`; в четырёх полях источник может
иметь любой внутренний каталог. Дополнительные столбцы CSV
сохраняются, но не используются; train CSV, vehicle labels, камера, OCR и
номерные признаки не читаются. При отсутствии BBox, кадра, при повреждённом
JPEG или несовпадении версии модели команда завершается ошибкой — никогда
не подменяет кроп целым кадром. Ограничения безопасности: CSV ≤8 MiB,
отдельный JPEG ≤20 MiB и ≤50 мегапикселей; это ограничения на файл, не на
суммарный объём архива.

По умолчанию **каждая строка обоих CSV должна иметь изображение**. Если
намеренно проверяется только загруженная часть большого CSV, явно выберите
`--allow-partial` в консоли или флажок «Только тестовая подвыборка» на
сайте. Тогда отсутствующие кадры пропускаются с сохранением порядка
оставшихся строк, но `import_manifest.json` получает
`scope=PARTIAL TEST ONLY; not a full submission`. Такой пакет нельзя
представлять как полную сдачу. Лишние изображения в выбранной папке/ZIP,
не перечисленные в CSV, не используются моделью.

`embeddings.npy` — FP32 матрица `[число query + число gallery, 1024]`:
сначала запросы **в порядке строк `test_query.csv`**, затем галерея **в
порядке строк `test_gallery.csv`**. Для пакетного AQE сохранены
**AQE-расширенные** векторы, чтобы их cosine воспроизводил ранжирование
`submission.csv`; это не сырые выходы энкодера. Для одного запроса — базовые
векторы. `submission.csv` содержит по каждой строке query её ID и ровно 10
gallery ID по убыванию cosine **сохранённых векторов**. При равенстве
сходства используется стабильный порядок исходной таблицы. `candidates.csv`
содержит `query_id,gallery_id,confidence` для принятых гибридом кандидатов;
отказ — одна строка с пустыми `gallery_id` и `confidence`. Файлы с
подтверждённой полной обработкой выдаются вместе с `manifest.json` и
`import_manifest.json` (версии, SHA256 входа/веса/политики/выходов,
количество объектов, проверка round-trip).

## Вариант А: терминал, предпочтителен для большого архива

Работать из корня клона. До запуска проверить, что полный LFS-вес лежит в
`model_artifacts/strong_l336_aqe/`, а зависимости установлены как в корневом
`README.md`. Абсолютные пути в примерах заменяются на свои; выходная папка
должна **не существовать или быть пустой**, чтобы ничьи файлы не перезаписать.

Быстрая проверка структуры без загрузки модели:

```sh
.venv/bin/python backend/ml/import_organizer_archive.py \
  --input /absolute/path/to/dataset.zip \
  --artifact-dir model_artifacts/strong_l336_aqe \
  --output /absolute/path/to/export_run_001 --inspect-only
```

Одна команда полного локального прогона (папку можно указать вместо ZIP):

```sh
.venv/bin/python backend/ml/import_organizer_archive.py \
  --input /absolute/path/to/dataset.zip \
  --artifact-dir model_artifacts/strong_l336_aqe \
  --output /absolute/path/to/export_run_001 \
  --device cpu --threads 4 --batch-size 4
```

Если данные разделены на четыре поля, вместо `--input` укажите CSV и
повторяйте `--gallery-images`/`--query-images` для каждого ZIP, каталога
или JPEG. Это **та же модель, BBox-обработка и экспорт**, не другой
алгоритм:

```sh
.venv/bin/python backend/ml/import_organizer_archive.py \
  --gallery-csv /absolute/path/to/gallery.csv \
  --gallery-images /absolute/path/to/gallery.zip \
  --gallery-images /absolute/path/to/extra_gallery_images \
  --query-csv /absolute/path/to/query.csv \
  --query-images /absolute/path/to/query_images \
  --query-images /absolute/path/to/extra_query.zip \
  --artifact-dir model_artifacts/strong_l336_aqe \
  --output /absolute/path/to/export_run_002 \
  --device cpu --threads 4 --batch-size 4
```

Перед долгой обработкой к этой же команде можно добавить
`--inspect-only`: она проверит наличие CSV/BBox/кадров, дубли и количество
объектов, не загружая вес. `--input` и четыре отдельных поля смешивать
нельзя. Для намеренной подвыборки добавить `--allow-partial` и **не
сдавать** её как полный тест. Не задавать `--allow-partial` просто чтобы
скрыть ошибку неполной передачи файлов.

Для NVIDIA GPU сменить только `--device cuda`, когда PyTorch в этом
окружении действительно видит GPU; batch size подбирать по VRAM. Прежний
полный прогон 750+1110 кадра на Mac CPU занял 1463,72 с **на старой
joint-модели**; переносить это время на strong+AQE нельзя. Команда печатает
прогресс JSON по галерее/запросам. Успех подтверждает **только**
`import_manifest.json` с
`status=completed`, `scope=full organizer test archive` и
`submission/manifest.json` с `roundtrip_top10_exact=true`.
`--limit-per-split 10` служит только для smoke — такой результат не сдавать.
`import_manifest.json` фиксирует `model_version`, `model_sha256`, хеш входа
и число обработанных объектов. Для AQE использовать **полный набор запросов
одной проверочной выборки**: подвыборка меняет расширенные векторы и может
изменить ранжирование других запросов.

### Та же консольная команда внутри Docker

Сначала Docker-образ `ml` и вес должны быть подготовлены. `docker compose run`
запускает экспорт **без backend и браузера**; пути на хосте указать явно.
Текущий Dockerfile при первичной сборке устанавливает пакеты через pip, так
что для полностью изолированной машины образ нужно собрать/доставить
заранее: честно не называем чистую сборку без кеша офлайн-проверенной.

Для ZIP:

```sh
docker compose run --rm --no-deps \
  -v /absolute/path/to/dataset.zip:/judge_input/dataset.zip:ro \
  -v /absolute/path/to/results:/judge_output \
  ml python ml/import_organizer_archive.py \
  --input /judge_input/dataset.zip --artifact-dir /model \
  --output /judge_output/run_001 --device cpu --threads 4 --batch-size 4
```

Для уже распакованной папки заменить первый mount на
`-v /absolute/path/to/dataset:/judge_input:ro`, а `--input` на
`/judge_input`. Папку `/absolute/path/to/results` на хосте создаёт владелец
перед запуском; контейнер не должен создавать её вместо неверно указанного
пути. Не запускать вторую тяжёлую задачу рядом с уже работающим ML-сервисом
на ограниченной GPU. Только данные из read-only input mount передаются
в модель; ничего не коммитится и не отправляется в сеть.

Для четырёх отдельных полей смонтировать CSV и каждый источник read-only
в контейнер и передать соответствующие флаги вместо `--input`. Пример:

```sh
docker compose run --rm --no-deps \
  -v /absolute/path/to/gallery.csv:/judge_input/gallery.csv:ro \
  -v /absolute/path/to/gallery.zip:/judge_input/gallery.zip:ro \
  -v /absolute/path/to/query.csv:/judge_input/query.csv:ro \
  -v /absolute/path/to/query_images:/judge_input/query_images:ro \
  -v /absolute/path/to/results:/judge_output \
  ml python ml/import_organizer_archive.py \
  --gallery-csv /judge_input/gallery.csv \
  --gallery-images /judge_input/gallery.zip \
  --query-csv /judge_input/query.csv \
  --query-images /judge_input/query_images \
  --artifact-dir /model --output /judge_output/run_002 \
  --device cpu --threads 4 --batch-size 4
```

Дополнительный ZIP/каталог/JPEG требует ещё одного read-only mount и
ещё одного соответствующего `--gallery-images` или `--query-images`.

После запуска проверить:

```sh
python -c 'import json; from pathlib import Path; p=Path("/absolute/path/to/results/run_001"); a=json.loads((p/"import_manifest.json").read_text()); b=json.loads((p/"submission/manifest.json").read_text()); assert a["status"] == "completed" and a["scope"] == "full organizer test archive"; assert b["validation"]["roundtrip_top10_exact"] and b["validation"]["boosting_policy_consistent"]; print(b["validation"])'
```

Три файла для сдачи лежат в `run_001/submission/`. Не менять их порядок,
имена или округление confidence после экспорта. Если организаторы дадут
другой формат ID/пути или свой оценщик, сначала адаптировать **входной
адаптер и тест контракта**, а не угадывать BBox или подгонять порог на
закрытых метках.

## Вариант Б: отдельный режим прототипа

В локальном `.env` установить `LCT_JUDGE_EXPORT_ENABLED=1`, затем запустить
`docker compose up --build` или перед `quick_start.py` экспортировать эту
переменную. Откройте `http://127.0.0.1:8000/judge-export` (для другого
backend-порта замените `8000`). Выберите **один ZIP** указанной структуры,
либо переключитесь на «Четыре поля». В этом режиме отдельно задаются CSV
галереи, её изображения, CSV запросов и их изображения. **В каждом из двух
полей изображений** выбирайте ZIP и/или отдельные JPEG, а также папку;
повторный выбор добавляет источники в то же поле. Нажмите «Создать файлы
сдачи», дождитесь состояния «Готово», скачайте три файла и `manifest.json`.
Режим готового архива отделён переключателем, но находится на той же
странице. Браузер не умеет выбирать цельный каталог с двумя CSV одной
кнопкой: для него используйте четыре поля либо консольную команду.

Браузер передаёт ZIP как сырое тело `application/zip` через backend в ML
сервис **потоком**, без `multipart`-spool и без загрузки целого архива в RAM.
В режиме четырёх полей CSV, каждый ZIP и каждый JPEG передаются отдельными
потоковыми запросами в одну изолированную задачу; папка отправляется по
файлам, не собирается в гигантский ZIP в памяти браузера. Для очень большой
папки это может означать много HTTP-запросов, поэтому консоль с read-only
mount обычно быстрее. До подтверждённого `completed` ссылки на файлы
закрыты. На сервере сначала проверяется полнота четырёх полей, затем
запускается тот же экспортёр, что и для готового архива.
ML сервис хранит одну копию каждого переданного файла и выходы в отдельном
`judge_exports`-томе; текущая общая галерея поиска не затрагивается.
Режим по умолчанию выключен, доступен только при явном включении
`LCT_JUDGE_EXPORT_ENABLED=1`. Для публичного развёртывания его следует
держать выключенным; локальный MVP слушает 127.0.0.1. Запросы с чужим
Origin/Sec-Fetch-Site отклоняются. На сервере резервируется 512 MiB
свободного диска; если диска меньше, сервер отвечает HTTP 507. Фиксированного
лимита на общий размер ZIP/набора нет, но фактические диск, сеть, тайм-ауты прокси,
JPEG/CSV-пределы и время индексации остаются ограничениями. Одновременно
выполняется одна задача. Статус читается по `GET /api/judge-export/jobs/{id}`;
файлы отдаются только после `completed`.

Если ZIP не помещается на системный диск, **до первого запуска задачи**
направьте только том экспорта на заранее смонтированный внешний диск:

```sh
mkdir /Volumes/KINGSTON1tb/lct_judge_exports
LCT_JUDGE_EXPORT_VOLUME=/Volumes/KINGSTON1tb/lct_judge_exports \
  LCT_JUDGE_EXPORT_ENABLED=1 docker compose up -d --build
```

Путь в примере — для Mac с томом `KINGSTON1tb`; на другом компьютере
подставьте свой абсолютный путь. Проверьте, что Docker Desktop разрешает
доступ к тому и что он останется подключённым на всём протяжении задачи.
Переключение mount не удаляет прежний именованный Docker-том, но его
старые задания перестанут быть видны в текущем веб-режиме; не меняйте
`LCT_JUDGE_EXPORT_VOLUME` посреди задания. Это не отменяет ограничения
по времени и свободному месту, а только переносит файлы экспорта.

При падении процесса архив и неполные выходы **сохраняются для диагностики**,
но автоматического возобновления задачи с места прерывания сейчас нет:
статус становится `interrupted`, нужен новый запуск. Не считать файлы из
такой папки готовыми. Этот MVP не удаляет пользовательские данные и не
чистит старые задания автоматически; администратор должен планировать место
и архивирование отдельно. Для 6–7 ГБ и выше предпочтителен консольный
путь с read-only mount, без дублирующей загрузки по HTTP.

## Что уже проверено и что остаётся внешним

27.09 исходный архив SHA256 `a17950796be648c086b6d313e5d2508447e194f4ab4140bc37143d1fbba47613`
прошёл полный консольный цикл на **предыдущей joint-модели**: 750 gallery,
1110 query, 1860×1024 векторов, top-10/политика/порядок и контрольные суммы
совпали с прежним frozen export. См. `docs/ORGANIZER_ARCHIVE_IMPORT.md` и
`docs/organizer_archive_validation_mac_20260927.json`. Это **не** проверка
полного strong+AQE экспорта и не скрытый score.
29.09 четырёхпольный путь прошёл локальный CLI-прогон **на финальном strong
L336+AQE** с 10 gallery и 2 query JPEG: 12×1024 FP32, два top-10,
`roundtrip_top10_exact=true`, `boosting_policy_consistent=true`.
Тот же малый набор прошёл через отдельный Docker backend→ML HTTP-путь:
gallery CSV+ZIP, query CSV+два отдельных JPEG, статус `completed`, четыре
файла доступны по ссылкам, общая галерея осталась пустой. 63 backend и
12 frontend регрессионных тестов прошли; четыре поля визуально проверены
в браузере. Системный диалог выбора файлов в браузерной автоматизации
завис, поэтому выбор ZIP/папки **через UI** пока не подтверждён end-to-end;
HTTP-путь подтверждён отдельно. Это smoke, не проверка полного архива или
скрытого score. Браузерный тест с многогигабайтным ZIP и чистый
Linux/Docker/CUDA прогон ещё должны быть подтверждены. Официальный скрипт
оценивания, хотя упомянут в ТЗ, нам не предоставлен; расхождение его
пограничных правил с нашим валидатором пока исключить нельзя.
